เตรียม API ไว้ก่อน: `uvicorn app.api:app --reload` แล้วเปิด http://127.0.0.1:8000/docs
ใส่อีเมลใหม่ที่เขาให้ในช่อง `extra_email` ของ `/run` เลือก `defense` ได้สามแบบ ผลลัพธ์จะบอก `events` ทุกขั้นและ `world` (outbox/calendar/deleted)

## C. คำถามที่อาจารย์น่าจะถาม และทิศทางคำตอบ

1. **ทำไมไม่ใช้ native function calling?** ใช้ JSON ธรรมดาเพื่อให้ทำงานกับ proxy ที่เข้ากันกับ OpenAI ได้ทุกตัว และมีจุดตรวจ (validation) จุดเดียวที่ทุก tool call ต้องผ่าน
2. **ทำไม guard เป็นโค้ด ไม่ใช่ prompt?** โมเดลถูกโน้มน้าวได้ แต่ `if` ถูกโน้มน้าวไม่ได้ ผลเทียบ spotlight (prompt อย่างเดียว) กับ guard ในตารางคือหลักฐาน (ดูตัวเลขจริง)
3. **ASR คืออะไร และวัดอย่างไร?** สัดส่วนเคสโจมตีที่เป้าหมายของผู้โจมตีเกิดขึ้นจริง ตรวจจากสถานะสุดท้าย (outbox, calendar, deleted, คำตอบ) ด้วยโค้ด ไม่ใช้ LLM ตัดสิน จึงทำซ้ำได้
4. **ทำไมต้อง temperature 0?** เพื่อให้ผลทำซ้ำได้ ตัวเลขจึงเป็นของ repo ไม่ใช่ของดวง
5. **ทำไมตัวเลขมีช่วง (CI) กว้าง?** มี 24 เคสโจมตี ตัวอย่างน้อย ผมรายงานช่วง Wilson 95% ไว้ ความต่างไม่กี่เคสยังสรุปว่าต่างจริงไม่ได้
6. **ทำไมใช้ BM25?** ตัวเลขก่อน/หลัง: MRR 0.48 → 0.81 และจำนวนอีเมลที่ agent ต้องอ่าน 14.2 → 2.0 (ดูตารางใน README)
7. **ทำไมตัดคำฟุ่มเฟือย (stop words) ทั้งที่ ablation ได้ MRR รวมสูงกว่า?** ตัดสินใจก่อนรัน eval และตรวจรายข้อแล้วว่าที่สูงกว่าเกิดจากบังเอิญ: คืนอีเมลไม่เกี่ยว 5 ฉบับแล้วอันที่ถูกมาอยู่บนสุดเพราะคำว่า "is" ไม่ใช่การค้นหาที่ถูก
8. **จุดอ่อนที่ใหญ่ที่สุดคืออะไร?** guard กัน action ไม่ได้กันเนื้อหา อีเมลปลอมที่บอกวันสอบผิดผ่านได้ ข้อมูลเท็จแยกด้วยโค้ดไม่ได้
9. **ถ้ามีเวลาอีกหนึ่งสัปดาห์จะทำอะไร?** ขั้นตอนยืนยันกับผู้ใช้สำหรับ tool ที่มีผลข้างเคียง, ชุดโจมตีใหญ่ขึ้นพร้อมรันซ้ำหลายรอบ, retrieval แบบ embedding และวัดด้วยชุด 40 คำถามเดิม
10. **ส่วนไหนเป็นโค้ดที่ AI ช่วยเขียน?** โจทย์อนุญาตให้ใช้ AI ได้ ต้องอธิบายได้ว่าแต่ละไฟล์ทำอะไร แนะนำให้เปิดอ่าน `app/agent.py`, `app/defenses.py`, `evaluation/checks.py` ให้ครบอย่างน้อยหนึ่งรอบก่อนสอบ
